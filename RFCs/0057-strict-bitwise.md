# RFC 0057：严格 32 位位运算

- 状态：Accepted
- 依赖：RFC 0001、RFC 0053

## 摘要

QuickCoffee 增加 `&`、`|`、`^`、`~`、`<<`、`>>`、`>>>` 及名称复合赋值 `&=`、`|=`、`^=`、`<<=`、`>>=`、`>>>=`。这是面向字节码的数值语义，不是 JavaScript 类型转换的兼容层：操作数必须已经是有限的有符号 32 位整数（`-2147483648` 至 `2147483647`），否则运行时失败。

## 语法与优先级

从低到高，位运算优先级为：`or`、位或 `|`、位异或 `^`、位与 `&`、相等比较、关系/成员比较、移位、加减、乘除（含 `//`、`%%`）、幂。前缀 `~x` 与 `-x`、`not x` 同属前缀表达式。

`&=` 等复合形式只接受普通名称，并且先读取一次名称、执行严格位运算、再写回；成员、索引和解构目标仍是编译期错误。

## 运行时模型

`&`、`|`、`^` 和 `~` 在有符号 32 位补码上计算，并以数值形式返回。`<<` 为按 32 位截断的左移，`>>` 为算术右移，`>>>` 为逻辑右移；移位计数必须是 `0..31` 的有限 32 位整数。逻辑右移的位模式仍以有符号 32 位整数表示，例如 `-1 >>> 1` 为 `2147483647`。移位溢出按 32 位包装，不暴露原型链或 JavaScript 内部对象。

## 编译与验证

编译器为每个运算生成独立字节码指令，验证器按二元运算消耗两个栈值、按一元运算消耗一个栈值并压回结果。名称复合赋值沿用 RFC 0053 的读—运算—写回路径。虚拟机在执行前检查有限性、整数性和 32 位范围，因此宿主嵌入与命令行执行具有相同错误边界。

## 验收

核心测试覆盖优先级、补码结果、三种右移、复合赋值、非法小数/越界操作数、非法移位计数以及成员目标拒绝；基准增加循环位运算负载，并与既有算术、循环和闭包负载同样进行三轮测量。
