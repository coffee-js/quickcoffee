# RFC 0028：函数 `return` 与结构化清理

- 状态：已采纳
- 依赖：RFC 0002、RFC 0004、RFC 0011

## 语法与语义

`return expression` 立即结束当前 QuickCoffee 函数，并将表达式值作为调用结果；裸 `return` 返回 `nil`。它只能出现于函数、箭头函数、`do` 函数或无原型工厂类的函数体中；顶层使用是编译错误。它不跨越嵌套函数：内层 `return` 只结束内层调用。

`return` 可以位于缩进块、条件和循环中。它离开所有正在进行的本函数循环，因此不会残留迭代状态。若位于 `try` 的受保护体或 catch 体中，先按词法由内向外执行适用的 `finally`，再返回。`finally` 内的 `return` 覆盖原来的待返回值；其错误同样按 RFC 0011 覆盖原来的控制结果。

后置条件不为 `return` 特设语法；需条件返回时使用 `if condition then return value` 或缩进块。

## 编译、VM 与验证

编译器在显式返回前依次发出所有活动数组/映射迭代器的 `IterEnd`，再退出每个活动 `Try` 处理器并内联其 finalizer。finalizer 编译时只保留外层清理上下文，故其中的 `return` 不会递归执行自身，却会正确触发外层 finalizer。

VM 仍以既有 `Return` 指令弹出当前调用帧；没有新解释器异常或非局部跳转机制。字节码验证器继续要求 `Return` 时值栈有返回值、迭代器栈与处理器栈均为空。这让不受信任字节码不能绕过 `finally` 或泄漏帧状态。

## 验收

测试覆盖普通与裸返回、嵌套条件、数组循环清理、catch 中返回、finally 执行、finally 覆盖返回、顶层拒绝，以及已编译 chunk 的验证。
