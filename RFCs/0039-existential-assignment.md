# RFC 0039：存在性赋值 `?=`

- 状态：已采纳
- 依赖：RFC 0001、RFC 0002、RFC 0015、RFC 0038

## 语义

`name ?= expression` 只在 `name` 尚未绑定或其当前值为 `nil` 时求值右侧并绑定；已有非 nil 值时返回该值且右侧完全不求值。该形式仅接受名称，不能用于成员、索引或解构，因而不会暴露 JavaScript 的可变属性模型。

普通名称读取仍严格：未绑定名称在 `name` 或 `name?` 中是错误。`?=` 是唯一允许把未绑定名称当作 nil 的语法位置。该规则保留了声明错误的可见性，同时支持配置默认值。

## 编译与验证

编译器将该表达式 lowering 为 `LoadOrNil`、`Dup`、`JumpIfNil` 和既有 `Store`。非 nil 分支弹出副本并保留原值；nil 分支清空两个 nil 后再计算右侧并存储。验证器将 `LoadOrNil` 视为压入一个值，现有控制流验证确保两条分支在汇合处具有相同栈深。

## 验收

测试覆盖已有值、nil、首次绑定、惰性右值、未绑定右值跳过，以及已验证反汇编 chunk。
