# RFC 0061：普通字符串转义

- 状态：Accepted
- 依赖：RFC 0001、RFC 0059

## 摘要

普通单引号和双引号字符串支持稳定、与宿主无关的字符转义。转义在词法阶段解码，运行时只接收 UTF-8 字符串值；双引号的 `#{...}` 插值规则保持不变，单引号仍不插值。

支持的转义如下：

| 形式 | 结果 |
|---|---|
| `\\0`、`\\b`、`\\f`、`\\n`、`\\r`、`\\t`、`\\v` | 对应控制字符 |
| `\\\\`、`\\'`、`\\"` | 反斜杠或引号 |
| `\\xNN` | 两位十六进制 Unicode 标量 |
| `\\uNNNN` | 四位十六进制 Unicode 标量 |
| `\\u{N...}` | 一至六位十六进制 Unicode 标量 |

## 严格错误边界

不完整、非十六进制、空的大括号形式、超出 Unicode 标量范围或代理项的转义均为 Parse 错误，并标注字符串所在源行。未列出的反斜杠形式也不被静默接受。该 RFC 不增加八进制转义，以避免歧义和隐式兼容 JavaScript 的历史行为。

## 多行与 heredoc

RFC 0059 的普通多行字符串在词法合并后使用同一转义解码器；RFC 0040 的三引号 heredoc 也通过同一解码器处理其规范化后的内容，因此保留换行与插值模式不变。

## 验收

核心测试覆盖控制字符、引号、十六进制、BMP 与补充平面的 Unicode 转义、单引号非插值、非法转义和 Unicode 标量错误；文档与五种文学手册均包含可执行示例。基准加入 `string-escapes` 负载并保留语义护栏。
