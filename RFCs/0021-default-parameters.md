# RFC 0021：函数默认参数

- 状态：已采纳

## 决议

函数形参可在名称后写 `= expression`：`(prefix, separator = '-', values...) -> expression`。带默认值的形参必须位于所有必选形参之后，`name...` rest 形参仍必须最后，且不可带默认值。

QuickCoffee 没有 JavaScript 的 `undefined`。调用时缺少可选形参，或明确传入 `nil`，都会在被调函数的词法环境中计算该默认表达式并覆盖该形参。因此默认值可以引用较早的形参、闭包变量和标准库；它不是调用方预先计算的值。

## 执行模型

函数常量保存形参模式、必选形参数量和可选 rest 名称。调用帧先将每个普通形参模式绑定为实参或 `nil`，再执行函数开头为默认参数生成的 `Load`、`JumpIfNil`、`Store` 小段字节码。默认值只允许命名形参，故这些指令仍有明确目标。这样不新增特殊调用协议，异常、燃料限制和闭包查找均沿用现有 VM 路径。

没有 rest 参数时，调用的实参不得多于全部普通形参数；实参不得少于必选形参数。该规则刻意不同于 JavaScript 的宽松缺参行为。

## 验证

`tests/rfc_core.rs` 覆盖省略与显式 `nil`、引用先前形参、词法捕获、与 rest 参数组合、错误的参数排序以及过量实参。正常与异常路径仍由 `Chunk::verify` 和 VM 帧机制验证。
