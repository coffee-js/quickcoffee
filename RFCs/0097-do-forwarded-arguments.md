# RFC 0097：`do` 立即调用的同名参数转发

- 状态：已采纳
- 依赖：RFC 0001、RFC 0020

## 动机

CoffeeScript 的 `do` 不只是零参数 IIFE；它会立即调用函数并转发参数。典型的循环闭包写法是 `do (filename) -> ...`，让每轮的外层 `filename` 成为该次调用的函数参数。QuickCoffee 原先始终发出 `Call(0)`，因此该写法会丢失外层值并在必选参数检查处失败。

## 契约

当 `do` 后面是函数字面量且形参全部为无默认值的普通名称时，每个形参名称同时从当前外层词法环境加载为调用实参，按形参顺序立即调用：

```coffee
left = 20
right = 22
do (left, right) -> left + right
# => 42
```

零形参 `do -> expression` 仍以零实参调用。为保持严格递归模式和参数校验，带默认值、rest 参数或数组/映射解构的 `do` 形参在解析阶段拒绝；`do` 后面的普通可调用表达式仍按零实参调用。转发实参在调用前于外层环境求值，未绑定名称照常产生运行时错误，不引入 `this`、原型链或 JavaScript `arguments`。

## 字节码与验收

编译器保留函数常量，然后为每个普通形参发出一次 `Load`，最后发出带准确参数个数的 `Call`；零参路径保持 `Call(0)`。验收覆盖一元/多元转发、零参兼容、循环闭包场景、参数顺序及复杂形参拒绝，并通过既有字节码验证、嵌入和 qtest 门禁。
