# RFC 0023：严格递归解构赋值

- 状态：已采纳

## 决议

赋值左侧可递归组合数组和映射模式：`[first, [middle, last]] = value`、`{point: {x, y}, labels: [_, name]} = value`。原有的 `a, b = value` 是顶层数组模式的简写；`{key, source: target} = value` 仍支持键名与绑定名不同。`_` 在任何深度均显式忽略对应值。

数组模式在每一层都要求数组和值数量精确相同；RFC 0071 为最后一项增加 `name...` rest，允许值数量不少于固定项。映射模式在每一层都要求映射包含所列的标识符键，但允许附加键。模式叶子只能是绑定名或 `_`。模式默认值、映射 rest 与字面字符串键分别由 RFC 0073、0075、0090 扩展；computed key 仍不支持。

## 字节码与原子性

编译器把模式嵌入单一 `Destructure(Pattern)` 指令，栈效应仍为消费并重新压入原右值。VM 递归读取所有容器、长度和键并收集绑定，只有整个遍历成功后才写入当前词法环境。因此任一深度发生错误都不会留下部分更新。

## 验证

`tests/rfc_core.rs` 覆盖数组套数组、映射套映射与数组、深层 `_`、类型/长度/缺键失败的原子性、正常 chunk 验证，以及手工构造 `Destructure` 栈下溢 bytecode 被验证器拒绝。
