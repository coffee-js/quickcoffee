# RFC 0071：数组模式 rest 绑定

- 状态：已接受
- 依赖：RFC 0008、RFC 0023、RFC 0026

## 摘要

数组解构模式的最后一项可以写为 `name...`，把未被前置模式消费的数组值绑定为一个新的数组。该能力适用于赋值、函数/工厂形参和 `for` 迭代绑定；映射模式不增加 rest 语法。

```coffee
[head, tail...] = [1, 2, 3]
tail # [2, 3]

collect = ([head, tail...]) -> [head, tail]
collect([1, 2, 3]) # [1, [2, 3]]
```

## 语义

数组模式中的 rest 必须恰有一个、必须是最后一项，并且只能绑定普通名称。前置项仍按 RFC 0023 的递归严格模式匹配；输入数组长度不得小于前置项数量，rest 没有剩余值时绑定空数组。整个匹配完成前不写入任何环境绑定，因此失败保持原子性。

rest 生成不可变公开数组值，不暴露宿主切片或内部数组存储；`for` 的每轮绑定仍先完整匹配再写入。参数模式的 rest 不改变外层函数参数个数或默认参数规则：它只消费该单个数组实参的尾部。

非法形式（`[tail..., next]`、多个 rest、映射 rest、顶层裸 rest）在解析或字节码验证阶段拒绝。非数组输入、长度不足或模式类型不符是运行时错误。数组普通 splat（`[head, values...]`）仍是构造表达式语法，不与模式 rest 混用。

## 字节码与验收

`Pattern::Rest` 只可出现在数组模式末尾；验证器递归检查其位置和命名约束。VM 先将所有固定项与尾数组匹配到临时绑定列表，成功后一次性提交。验收覆盖赋值、空尾、函数参数、循环绑定、嵌套模式、非法位置、短数组、原子失败和恶意字节码验证。
