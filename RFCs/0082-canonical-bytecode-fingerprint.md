# RFC 0082：规范化字节码指纹编码

- 状态：已采纳
- 依赖：RFC 0078、RFC 0080

## 动机

RFC 0078 的指纹必须适合作为长期缓存键。若直接哈希 Rust `Debug` 输出，工具链改变展示格式即可令相同字节码产生不同键，且这种变化并非 QuickCoffee 语义变化。

## 编码契约

`Chunk::fingerprint()` 与 `Program::fingerprint()` 使用显式二进制逻辑编码后计算 FNV-1a 64 位哈希：每个枚举变体有固定标签，字符串带 UTF-8 字节长度，集合带元素数量，整数按小端固定宽度编码，浮点数按 `f64::to_bits()` 编码。函数常量递归编码形参、默认值块和函数块；映射按其 `BTreeMap` 的既定键序编码。指纹编码不使用 `Debug`、`Display`、地址或 `Rc` 身份。

指纹只描述字节码内容与常量，不描述 VM fuel、宿主全局、上下文或执行状态。相同编码产生相同 `u64`；语义或指令内容改变时应产生不同指纹（仍受 64 位哈希碰撞概率约束）。已有 API 类型和 CLI 十六进制格式不变。

## 验收

核心测试必须覆盖共享程序与复制句柄稳定、常量内容变化可区分、函数/模式/映射递归编码，以及验证后的 CLI 指纹仍不执行脚本。实现不得依赖 Rust 调试格式化。
