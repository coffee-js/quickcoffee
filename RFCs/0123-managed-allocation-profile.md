# RFC 0123：托管分配剖析

- 状态：已采纳
- 依赖：RFC 0066、RFC 0081、RFC 0103、RFC 0122

`ExecutionStats` 增加 `value_allocations` 与 `environment_allocations`。前者统计执行期新建的引用计数字符串、数组、映射与字节码函数后备存储，包括 VM 指令、模式绑定、异常字符串及标准库返回值；后者统计 QuickCoffee 函数调用创建的词法环境。编译期常量、Rust 临时集合的容量变化以及嵌入宿主原生回调内部创建的值不计入。

这两个字段是确定性的分配事件数，不是字节数、存活对象数或系统分配器调用次数。数组原地追加仅在 `Rc` 写时复制确实创建新后备存储时计数。成功、运行时错误与资源错误均保留已发生事件；编译和验证失败继续沿用既有 `last_execution()` 契约。

RFC 0146 在不改变上述历史字段的前提下，另增覆盖完整语言值类别的逻辑对象数与规范化 payload bytes；调用方不得把本 RFC 的旧事件数解释为该新模型的 retained memory。

`qcoffee --stats` 追加这两个字段。`qbench` 在各负载计时完成后执行一次不计时的相同语义护栏，并在既有 `quickcoffee.qbench.v1` 记录中追加 `profile_*` 字段：指令、调用深度、RFC 0122 的六类热点及本 RFC 的两类分配。所有 `profile_*` 值均代表一次执行，不乘以 `iterations` 或 `repeat`；新增字段不改变现有 v1 字段含义。

验收包括字节码闭包、容器、函数环境、标准库分配、宿主回调排除、模块图累计、qcoffee 文本统计以及 qbench JSON/文本字段。计数不得改变值、错误种类、fuel 消耗、字节码指纹或计时区间。
