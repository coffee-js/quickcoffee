# QuickCoffee 0.1 syntax scope

For a section-by-section comparison with the CoffeeScript 1.12.7 language reference, including explicit **Implement**, **Adapt**, and **Reject** decisions, see the [CoffeeScript 2016 feature matrix](coffeescript-2016-matrix.md).

Embedding diagnostics expose ordered primary/secondary labels through `Error::labels()`. A `SourceSpan` carries an optional opaque source name, a start coordinate, and an optional exclusive end; columns are one-based Unicode scalar positions. Lexer and parser errors carry precise ranges when their physical line was not rewritten by preprocessing; synthetic or rewritten input remains line-only rather than inventing a column. `compile_named`, `compile_program_named`, and `Context::eval_named` preserve a host-supplied name verbatim on existing labels; named modules and CLI file input do the same. Anonymous calls remain unnamed, and `Error::position()` remains the compatibility accessor for the primary start.

Lowering-time errors for `break`, `continue`, and `return`, single-file misuse of module directives, and duplicate module exports retain the triggering keyword span. These validation spans do not alter public bytecode; transformed input continues to degrade to a reliable line rather than a guessed column.

Compiled `Program` values keep a private source-map sidecar for top-level expressions, nested/default-parameter chunks, assignment/destructuring statements, modules, verifier failures, runtime failures, host-call failures, and resource stops. It is excluded from bytecode fingerprints and disassembly, and source-map lookup happens only on compile/VM error paths. Runtime errors retain a primary failure label followed by nearest-to-outermost `called from here` secondary QuickCoffee call sites. Raw host-built `Chunk` values remain deliberately unattributed.

`Engine::check_program*` performs static compilation without execution and may return several independently recoverable parser errors. Recovery is deliberately limited to deterministic top-level statement boundaries; ordinary `compile*` APIs retain their one-error result. `qcoffee --check FILE` prints the collected parser errors in source order to stderr, with no stdout and no bytecode execution.

Embedding callers may use `Program::fingerprint()` as a deterministic single-program bytecode cache key. `Engine::fingerprint_module_graph(entry, loader)` instead loads and verifies the complete static graph without executing modules and returns a v1 `u64` cache key sensitive to dependency sources, canonical names, imports/exports, and edges. `MODULE_GRAPH_FINGERPRINT_VERSION` identifies its canonical encoding independently of bytecode fingerprints.

`RuntimeBuilder` configures independent bounded Program and Module compilation caches, and `Runtime::context_builder()` creates isolated Contexts that share only those verified artifacts. Cache identity includes the complete optional source name and raw UTF-8 source; exact hits use deterministic least-recently-used retention, failed compilation is not inserted, zero capacity disables a cache, and `cache_stats()` / `clear_compile_caches()` make ownership explicit. Globals, native bindings, evaluated module exports, fuel, cancellation, execution statistics, and retained-memory state remain Context-owned. Runtime is currently same-thread because Programs and VM values use `Rc`; it is deliberately not `Send` or `Sync`.

`CompileLimits` independently bounds one raw UTF-8 source (default 1,000,000 bytes), recursively reachable instructions in one Program or Module (1,000,000), unique canonical modules in a static graph (1,024), and cumulative raw graph source (16,000,000 bytes). Source is checked before `.litcoffee` extraction and cache-key copying; failed compilation does not query or pollute Runtime caches. `Context::run_program` rechecks foreign or host-built Program artifacts under the owning Runtime policy. Module execution and graph fingerprinting share the same graph budget, and execution loads, compiles, resolves, and validates the complete static graph before any module script runs. `qcoffee` exposes the same policy through `--max-source-bytes`, `--max-bytecode-instructions`, `--max-module-graph-modules`, and `--max-module-graph-source-bytes`. `ResourceLimit` is non-exhaustive, so embedding matches must retain a wildcard arm.

Opt-in contextual natives receive a `NativeCallContext` and arguments. They can cooperatively check cancellation, read `ResourceLimits`, charge deterministic host work against fuel, record logical managed object/byte telemetry, downcast one Context-owned `HostState`, and retrieve explicitly allowlisted typed handles from `HostCapabilities`. `CapabilityKey<T>` classifies each script-invisible slot as clock, random, logging, file, or network without supplying any system implementation; missing or type-mismatched slots return `None`. Module children inherit the same handles, independent Contexts are isolated by default, and host bindings are excluded from globals, serialization, Runtime caches, and retained-memory census. Existing `add_native` callbacks keep their simpler path. Synchronous callbacks run inline on the calling thread, cannot be forcibly interrupted, and host panics are neither caught nor transactionally rolled back. Runtime and Context are deliberately non-`Send`/non-`Sync`; only `CancellationToken` is cross-thread. This 0.x embedding API follows the RFC 0154 patch/minor migration contract.

Cargo package metadata links embedding users to the repository, README, license, and docs.rs API.

`qtest --timeout-ms N` runs every selected file in an isolated Context worker, cooperatively cancels it after N positive milliseconds, records a normal per-file failure, and continues in deterministic input order. It does not replace fuel or resource limits, and cannot forcibly stop a synchronous non-cooperative host callback; qtest exposes no such callback injection surface by default.

`qtest --module-root ROOT ENTRY...` explicitly grants one restricted file-module root. Every canonical root-relative entry is preflighted into an in-memory `ModulePackage`, executed in a fresh Context, and passes only when it exports the strict Bool `test = true`. Module cases reuse fuel, per-case timeout, stats, filtering/listing, JSON, TAP, and JUnit contracts. Ordinary file mode retains no module authority.

`qtest --junit FILE` writes one byte-stable UTF-8 JUnit XML report after the selected files finish. It can accompany plain, JSON, or TAP output; it XML-escapes case paths and failures, but deliberately omits measured time.

The standalone `qcson` converts explicit files or stdin bidirectionally between data-only CSON and canonical JSON. Successful data stays on stdout, versioned `quickcoffee.qcson-diagnostic.v1` failures stay on stderr, and the tool never executes its input or grants script capabilities. Rust embedders can call the public default-limit or explicit-`ResourceLimits` `parse_json` / `encode_json` APIs and their CSON counterparts directly; all remain in-memory and free of ambient I/O.

The bundled `qtest --json` runner emits one stable JSON result per file for CI and host integration; `qtest --tap` emits deterministic TAP 13 records; `qtest --filter TEXT` selects matching paths and `qtest --list` enumerates the selected files without executing them. `qcoffee --json` emits one stable JSON value or structured error for a single execution. `qcoffee --fingerprint FILE` prints a stable 16-digit hexadecimal key for verified bytecode without executing it, while `qcoffee --fingerprint --module-root ROOT ENTRY` prints the separately versioned full restricted-module-graph fingerprint in the same format; both use canonical encoding rather than Rust debug text. `qbench --json` emits guarded compile/verify/execute timing records; `qbench --list` enumerates workloads and `qbench --only NAME` runs one selected workload, while the default remains the complete suite. `qdocco --markdown` renders literate notes, fenced source, and final values with a stable template-version marker; `--incremental` preserves an existing artifact when the final rendered bytes are unchanged, without skipping execution. Embedders can adjust compilation boundaries through `CompileLimits`, or fuel, maximum QuickCoffee-call depth, and general String/Array/Map plus JSON/numeric execution boundaries through `ResourceLimits`; they may also supply a `CancellationToken`. The resulting structured resource errors cannot be caught by scripts. `IntoValue` and `TryFromValue` recursively bridge common owned Rust scalars, `Vec`, `BTreeMap<String, T>`, and `Option` without executing code or coercing Number, Integer, or Decimal. They can also chain `Context::with_global` and `Context::with_native`; `cargo run --example embed` is a compiled host integration example. Execution statistics remain on stderr with `--stats`.

`Context::retained_memory()` reads a deterministic logical object/byte snapshot of values reachable from that Context's globals. It deduplicates shared values and cycles, excludes the shared builtins and host callback internals, and is neither RSS nor a peak or hard memory limit.

An embedder that needs a repeatable observation high water calls `Context::sample_retained_memory()` at its chosen business boundary, then reads the component-wise lifetime maximum with `Context::retained_memory_high_water()`. Sampling is deliberately explicit: it does not traverse the graph after every VM instruction or execution, so it is not a full live-memory peak or a hard limit.

`ResourceLimits::with_max_retained_managed_objects` and `with_max_retained_managed_bytes` set optional Context-rooted retained-state commit guards. An already-over-budget Context is rejected before bytecode runs; a run that would leave too much retained state fails with an uncatchable resource error and restores its prior globals, closures, class static fields, and instance fields. These guards do not cap transient allocations during a run, RSS, or a complete live-memory peak.

`ResourceLimits::with_max_transient_managed_objects` and `with_max_transient_managed_bytes` set separate, default-disabled cumulative allocation guards for one run. Existing RFC 0146 VM/standard-library accounting points check the limits immediately after recording their complete delta; contextual natives participate through cooperative `record_managed_allocation`, and a static module graph shares one aggregate ledger. A breach is uncatchable, keeps failure-point statistics, and restores script-owned mutable Context state. The budget restarts for the next top-level run and remains distinct from RSS, allocator capacity, an instantaneous live peak, and the retained graph.

`qbench --compare-qjs PATH --compare-iterations 1 --repeat 11 --json` emits a separate `quickcoffee.qcompare.v1` same-machine comparison. The caller supplies PATH; the suite covers scalar loops, function calls, array construction/indexing/iteration, map lookup/functional update, and Unicode scalar iteration/indexing. Records separate startup, compilation, precompiled hot execution, and end-to-end CLI time, so they must not be compared directly with in-process `qbench.v1` fields. Because JavaScript string indexing addresses UTF-16 code units, the Unicode indexing workload predecodes scalars with `Array.from` to match QuickCoffee's result semantics; that adapter does not make the underlying operations identical.

Integer ranges are ascending or descending: `[2..4]` is `[2, 3, 4]`, `[4..2]` is `[4, 3, 2]`, and exclusive forms omit the end (`[4...2]` is `[4, 3]`). Bounds must be finite integers and oversized ranges are rejected.

Array and Unicode string indexing accepts negative finite integers (`items[-1]`, `'a☕中'[-2]`); out-of-range indices remain errors.

Map destructuring accepts identifier or literal string keys (`{"first-name": first} = record`) and may capture unlisted keys with a final named rest pattern (`{id, ...metadata} = record`); keys remain literal (computed expressions are not evaluated), explicit fields remain strict, and the captured map is immutable.

Map literals support left-to-right spread (`config = {...defaults, theme: 'dark'}`); each spread must evaluate to a map and later entries override earlier keys.

Destructuring array and map members may use dynamic defaults (`[first = 1, second = first + 1] = [nil]`); missing or `nil` values evaluate defaults in the current lexical environment, with strict atomic matching.

This is the English index of RFC 0001. An omitted CoffeeScript 2016 feature is deliberately unsupported, not silently compatible.

Static named modules are available to embedding callers: `Engine::compile_module` accepts `import { public as local } from 'name'`, `export name = value`, and `export { local as public }`; `Context::run_module` obtains source solely through a host `ModuleLoader`, isolates module globals, reuses dependencies, rejects cycles, and shares fuel/cancellation across the graph. `Engine::fingerprint_module_graph` uses the same loader boundary to load and verify, but not execute, the full static graph; its versioned cache key covers the entry, raw sources, Program fingerprints, imports/exports, and canonical dependency edges, and failures never yield a partial key. `Engine::prepare_module_package` and `Runtime::prepare_module_package` turn one such complete preflight into an immutable in-memory snapshot; `Context::run_module_package` never calls a loader and creates fresh private module globals and exports on every run. Hosts explicitly rebuild a package when source changes. Hosts may explicitly construct `RestrictedFileModuleLoader` for `.coffee` or `.litcoffee` UTF-8 files beneath one canonical root: imports require `./` or `../`, omitted extensions become `.coffee`, and lexical traversal, absolute/bare names, platform-specific separators, and symlink escapes are rejected. The CLI explicitly grants that authority with `qcoffee --module-root ROOT ENTRY` for execution or `qcoffee --fingerprint --module-root ROOT ENTRY` for fingerprint inspection. Ordinary file/stdin, `-e`, and REPL modes never gain implicit module authority.

The standard library is ordinary functions: `print`, `len`, `type`, `error`, `range`, `str`, `trim`, `contains`, `starts_with`, `ends_with`, `replace_all`, `sort`, `concat`, `parse_json`, `encode_json`, `integer`, `number`, `decimal`, `decimal_div`, `round_decimal`, `abs`, `sum`, `min`, `max`, `keys`, `values`, `join`, `split`, and `assert`. Aggregators accept homogeneous finite Number, Integer, or Decimal arrays; `sum([])` is Number `0`, while `min([])` and `max([])` are errors. String predicates are strict, case-sensitive, and normalization-free; `trim` removes only RFC 0139's pinned Unicode White_Space scalars and reads no locale or host Unicode table. `replace_all(text, needle, replacement)` performs case-sensitive, normalization-free, left-to-right non-overlapping literal replacement without rescanning inserted text; an empty needle is an error, and `TextOperationBytes` / `StringBytes` independently bound scanning input and final output. `sort(array)` returns a new stable ascending array of homogeneous finite Number, Integer, Decimal, or String values; strings use locale-free Unicode-scalar lexicographic order and the input-item boundary comes from `ResourceLimits`. `concat(left, right)` immutably joins exactly two Strings or two Arrays and checks output and collection-operation limits before allocation.

`123n`, `0xffn`, `0b101n`, and `0o755n` are arbitrary-precision Integer values. Integer and IEEE-754 Number remain strictly distinct, with no mixed arithmetic or ordering. Integer supports exact arithmetic, signed bitwise operations except `>>>`, ranges, indices/slices, and `by` steps. `integer(value)` and `number(value)` provide explicit conversions, and Integer-to-Number conversion is restricted to the safe-integer range. `ResourceLimits::max_integer_bits` bounds constants, globals/native results, operations, aggregation, and JSON before the value becomes script-observable; `IntegerBits` failures are uncatchable. RFC 0135 defines the complete contract.

`12m`, `0.1m`, and `1e2m` are normalized exact Decimal values for money and rates. Decimal, Integer, and IEEE-754 Number are strictly distinct; mixed arithmetic, ordering, and aggregation fail. Exact Decimal `/` rejects repeating results; `decimal_div(left, right, scale, mode)` and `round_decimal(value, scale, mode)` require one of `down`, `up`, `floor`, `ceiling`, `half_up`, or `half_even`. `decimal(value)` accepts Decimal, Integer, or decimal text but deliberately rejects Number; Decimal-to-Integer/Number conversion succeeds only when exact. Context coefficient-bit and scale policies cover constants, globals/native results, alignment/comparison, arithmetic, rounding, conversion, aggregation, and JSON with uncatchable `DecimalCoefficientBits` / `DecimalScale` failures. RFC 0137 defines the absolute compile/host ceiling, host access, and tagged CLI JSON.

`parse_json(string)` maps integer tokens to exact Integer and fractional/exponent tokens to exact Decimal without `f64`; duplicate object keys and invalid escapes fail. `encode_json(value)` emits compact canonical Map-key order, preserves Integer/Decimal text, and rejects Error, Function, Class, Instance, and non-finite Number. RFC 0118/0138 define the JSON size boundaries and `Context::with_resource_limits` / `set_resource_limits`; valid JSON numbers also use the RFC 0135/0137 numeric categories. Crossing a boundary is an uncatchable Resource error, while syntax and unsupported-value errors remain catchable. This script facility is separate from the `qcoffee --json` result protocol.

`error(code, message[, data[, cause]])` creates a sealed Error. `catch` binds Error and exposes only `code`, `message`, `data`, and `cause`; ordinary VM/host failures use code `runtime`, while throwing a non-Error uses `throw`. Trusted source labels and call context stay host-only, and Resource failures remain uncatchable. RFC 0136 defines the complete contract.

Ordinary single- and double-quoted strings decode `\\0`, `\\b`, `\\f`, `\\n`, `\\r`, `\\t`, `\\v`, quote/backslash escapes, two-digit `\\xNN`, four-digit `\\uNNNN`, and one-to-six-digit `\\u{...}` Unicode escapes. They may span physical lines; a normal newline becomes one space and indentation inside the string is ignored. A single unescaped backslash at the line end removes both the backslash and the newline. Double-quoted multiline strings retain `#{expression}` interpolation, while single-quoted strings remain literal. Triple-quoted heredocs preserve newlines: `"""…"""` interpolates and `'''…'''` is literal; an unclosed delimiter or invalid escape is a lexical error.

`for` uses strict recursive patterns for its bindings: `for [left, right] in pairs then left + right` and `for own _, value of record then value` are supported. A pattern mismatch is a runtime error and never partially updates that iteration's bindings.

Array comprehensions may bind an optional zero-based index: `for value, index in items then value + index`; with `by step`, the index is the actual stepped array position. Array patterns may bind a final rest name, such as `[head, tail...] = items`; the tail is a new immutable array and a rest pattern must be final.

Comprehensions may also use CoffeeScript's postfix form: `value * 2 for value in items`, optionally wrapped as `[value * 2 for value in items]`. The postfix form has the same `by`, `when`, map, pattern, `break`, and `continue` semantics as the prefix form; the brackets are a comprehension delimiter and do not add a nested array.

String indexing and strict slices use Unicode scalar boundaries: `'a☕中'[1]` is `'☕'`, and `'a☕中'[1..2]` is `'☕中'`. String `for` iteration accepts a non-zero finite signed `by` step over Unicode scalar positions: `for character, index in 'a☕中x' by 2 then index` yields `[0, 2]`, while `by -2` starts at the end.

`do` immediately invokes a function; `do (name, other) -> ...` forwards same-named outer values, while defaults, rest, and destructuring are rejected in `do` parameters. `do -> ...` remains a zero-argument IIFE.

`!` is a strict Bool alias for `not`; `!=` remains strict inequality. Non-Bool operands such as `!1` are runtime errors.

Array and string `by step` expressions are evaluated once and must be non-zero finite integers; positive steps start at the first item and negative steps start at the last item. Map iteration excludes `by`.

Names support arithmetic compound assignment (`+=`, `-=`, `*=`, `/=`, `%=` and `**=`). Compound assignment is intentionally name-only; members, indexes, and destructuring remain immutable API boundaries.

Names also support prefix and postfix numeric updates: `next = ++counter` yields the new value, while `previous = counter--` yields the old value before decrementing. `++` and `--` are name-only and use strict numeric arithmetic; members, indexes, and destructuring are rejected.

Arithmetic also includes CoffeeScript's floor division `a // b` (`floor(a / b)`) and dividend-dependent modulo `a %% b` (`(a % b + b) % b`). `%` remains the ordinary remainder, and `//=`/`%%=` are name-only compound assignments.

Bitwise operators are strict signed-32-bit numeric operations: `&`, `|`, `^`, prefix `~`, `<<`, arithmetic `>>`, and logical `>>>`. Operands must be finite integers in the signed 32-bit range; shifts accept counts `0..31`, and `&=`, `|=`, `^=`, `<<=`, `>>=`, `>>>=` are name-only compound assignments. This is QuickCoffee's bytecode model, not JavaScript coercion; logical-right-shift results are represented as signed 32-bit numbers (`-1 >>> 1` is `2147483647`).

An explicit operator at the end of a physical line continues the same expression on the next line: `total = 1 +\n  2 * 3`. Assignment, arithmetic, comparison, logical, membership, bitwise, shift, and power operators may continue; `?` is excluded so postfix `value?` remains a complete line. `->` and `=>` still introduce their ordinary indented function body. Continuation indentation is layout-neutral until the expression ends.

Pure literal arithmetic, comparisons, collections, and interpolation are folded into verified constants at compile time; dynamic names and strict expressions that may fail at runtime remain on the VM path. Multiline arrays and maps may omit commas at physical line boundaries (`[\n  1\n  2\n]` and `{\n  first: 1\n  second: 2\n}`); parentheses and call arguments still require explicit separators.

Maps may also use indentation after a standalone assignment: `record =` followed by indented `first: 1` entries lowers to a prototype-free map. Nested map entries are recursive; an ordinary assignment continuation such as `value =` followed by `1 + 2` is not treated as a map.

Supported: decimal, hexadecimal (`0xff`), binary (`0b1010`), octal (`0o755`), and scientific-notation numbers; strings (double quotes support `#{expression}` interpolation), booleans including CoffeeScript aliases (`yes`/`on`, `no`/`off`), `nil`, arrays including integer range literals (`[1..3]` inclusive, `[1...3]` exclusive) and splats (`[head, items...]`), maps including identifier shorthand (`{name}`), indexing and strict array/string slices (`items[start..end]` inclusive, `items[start...end]` exclusive), map-only member access (`record.name`), nil-safe member/index/slice/call suffixes (`record?.name`, `record?[key]`, `items?[start..end]`, `fn?(args)`), postfix non-nil tests (`value?`), name-only existential assignment (`name ?= value`), arithmetic/comparison/logical expressions including strict-equality aliases `is`/`isnt`, short-circuit chained comparisons (`a < b < c`), and nil-specific fallback (`left ? right`), array membership (`value in array` / `value not in array`) and own-map key membership (`key of map` / `key not of map`), `if`/`unless` (including postfix conditions), `while … then …`, `until … then …`, statement-position postfix `body while/until condition`, infinite `loop …`, filtered array `for pattern in xs [by step] when condition then …`, map `for own key_pattern, value_pattern of map then …`, `switch`/`when`, `try`/`catch`/`finally`, `throw`, function-only `return`, `break`, `continue`, strict recursive assignment and parameter patterns (`([a, b], {factor}) -> …`), bare-name `x, y -> …` closures, expression-bodied `->` closures including named trailing default parameters (`y = 2`), rest parameters (`tail...`), and splat calls (`f(items...)`), and zero-argument `do function` IIFEs. A `for` expression collects body values into a new array; rejected `when` values and `continue` are omitted, while `break` returns the accumulated prefix. Array and string slice bounds are finite in-range scalar integers; negative bounds count from the sequence end and no implicit clipping occurs. `value?` is false only for nil and does not suppress an unbound-name error; `?=` is the sole form that treats an unbound name as nil and short-circuits its right side otherwise. Chains retain their middle operand once and short-circuit; aliases preserve Bool and strict QuickCoffee equality with no coercion. A soak suffix short-circuits only a nil receiver; non-nil access remains strict. Omitted or `nil` named optional arguments use the default; required parameters must come first. Defaults, rest, and patterns require parenthesized lambda parameters. Array and string `by step` evaluate a non-zero finite integer once; negative steps start at the last item, and map iteration excludes it. `loop` is `while true` and remains fuel-limited. `return expression` exits only its current function, while bare `return` yields `nil`; it cleans active loops and runs enclosing finalizers. Calls may omit parentheses on one logical line (`f a, b`); explicit `f(a, b)` remains required across layout boundaries and for ambiguous grouping.

Identifiers use Unicode XID rules: XID start or `_` first, XID continue or `_` after, with no normalization. `#` is a line comment; non-nesting `### … ###` block comments are removed before layout. Excluded: embedded JavaScript, global/free `this`, arbitrary-function construction, public prototype capabilities, regexes, computed map-pattern keys, unparenthesized default/rest/destructuring parameter forms, generators, async, and member/index/destructuring `?=`. Space-only indentation blocks are supported for multi-statement bodies. Indented classes support constructors, instance/static methods, class-confined `this`/`@`, dedicated Class/Instance values, confined field writes, receiver-aware calls, `new`, private `extends` chains, statically resolved `super`, and safely escaping receiver-bound `=>`; the historical factory form produces a migration diagnostic. Conditions accept only booleans and names must be declared by assignment or the host.

Implicit calls are supported on one logical line: `print value`, `add 20, 22`, `double add 20, 22`, and `len [1, 2, 3]`. Their arguments use ordinary expression precedence; explicit parentheses remain required for calls spanning layout boundaries.

`map_set(map, key, value)` and `map_delete(map, key)` require String keys and return new lexically ordered Maps without mutating their inputs. RFC 0159 defines their pre-allocation collection-operation and Map-entry limits.

## Benchmark statistics

`qbench --json --repeat 11` reports the upper median and a `*_mad_ns` (median absolute deviation) dispersion value for compilation, verification, and execution. `qbench --compare-qjs PATH` reports separate medians and MAD values for startup, compilation, precompiled hot execution, and CLI-total time for both runtimes.

The separate `fuzz/` cargo-fuzz package pins its nightly toolchain and exposes parser, verifier, and resource-bounded VM execution targets. `make fuzz-smoke` runs each with fixed reviewed seeds, bounded input, and a fixed run count; confirmed crashes are minimized and promoted to normal regression tests. Scheduled/manual quality checks interpret the applicable library tests with isolated Miri, while `make dependency-audit` checks both root and fuzz lockfiles against RustSec.
